# 能力边界与证据分层

这份文档回答两个问题：**提示词到底能改变什么**、**agent 能不能自主优化自己的提示词**。结论按可信度分层，机制推断与文献结论分开标注，不混着说。

---

## 一、把"提示词提升参数表现"拆开看

一个 agent 在某一轮的可观测行为，可以写成四个自变量的函数：

```
行为 = f( θ 权重,  c 上下文,  τ 推理预算,  A 可用工具 )
```

- **θ**：模型权重。推理期冻结，任何提示词都改不了它。所以"用特殊提示词提升参数能力"是范畴错误——不是效果好坏的问题，是这句话没有指称对象。
- **c**：上下文。提示词**只**作用在这里，外加系统提示、检索内容、工具返回。
- **τ**：每个答案消耗多少前向计算。提示词能间接影响（"先列步骤再答"会拉长生成），但不能突破 max_tokens、不能改采样温度。
- **A**：工具。提示词能决定调不调、按什么顺序调。

**所以：如果"参数表现"指的是权重层面的能力，答案是不可能；如果指的是同一权重下的可观测输出质量，答案是可能，但机制是"改变条件分布 + 改变计算分配"，不是"增强能力"。** 这个区别不是抠字眼——它决定了优化的上限在哪，以及什么时候该停止调提示词去换模型、换工具、改流程。

### 提示词真实生效的四个通道

| 通道 | 机制 | 稳健度 |
|---|---|---|
| **信息补全** | 补上模型无法从训练分布推断的私有信息（路径、口径、字段、验收标准） | 最高。这本质是"减少猜测"，不是"提升智力" |
| **方差压缩** | 消歧义、定格式、给样例 → 输出分布变窄，pass@1 上升，但 pass@k 上限不变 | 高。代价是牺牲多样性 |
| **计算重分配** | 要求分解、回代验算、多次采样投票 → 把预算从"生成"挪到"校验" | 中。仅在任务本身需要串行计算时有效 |
| **轨迹选择** | 角色、格式前缀、措辞微调 → 改变采样落在分布哪个区域 | 低且不稳定。同义改写就能造成大幅波动 |

## 二、证据分层

### 第 1 层：稳健，可依赖

- **规格完备度**。缺验收标准、缺输出格式、缺输入指向时，模型只能猜，猜错率高。补上就改善——这不是模型变强，是任务变明确。**这是本技能收益的主要来源，也是唯一可以声称"必然有效"的部分。**
- **材料锚定**。要求逐条标注出处、明确"材料没有就说没有"，能显著压低编造。机制是切断开放式生成，把任务收窄成抽取+校验。
- **输出契约**。格式一旦固定，可机械校验，返工成本骤降。
- **少样本样例**。样例是压缩过的规格，信息密度高于等长规则描述。注意样例偏差会主导输出分布，需含负例。

### 第 2 层：有条件，看任务

- **思维链（CoT）**。文献结论：收益集中在需要多步符号运算的任务（算术、逻辑、形式推理）；对简单检索式问答收益接近零，甚至因引入无关推理而变差。**不要无条件加"让我们一步步思考"。**
- **自一致投票（self-consistency）**。前提是答案唯一且模型准确率高于随机。成本随采样数线性增长，答案开放（写作、设计）时无效。
- **自我精炼（self-refine）**。文献结论：**有外部验证器时有效；纯靠模型自查、没有外部信号时，推理类任务常常不升反降。** 这条直接决定了本技能的做法——优先用脚本、测试、回代验算做校验，而不是"再想一遍"。
- **约束数量**。文献结论：模型对多条约束的同时遵守率随约束数量下降，长上下文中段信息利用率低。**所以不是约束越多越好**，这也是 SKILL.md 里 I5 长度预算的依据。

### 第 3 层：噪声，别当方法论

- **人设前缀**（"你是世界级专家"）。多次对照实验显示对事实准确率影响很小或为负，主要改变语气而非正确性。
- **情绪施压**（"这对我很重要""做不好我会被开除"）、"深呼吸""一步一步来"这类咒语。有个别研究报告增益，效应量小、难跨任务复现，更像提示词敏感性的产物而非稳定机制。
- **同义改写带来的性能波动**。这恰恰是**反证**：如果换个说法就能差出十几个点，说明单次测量不可信，任何"我改完更好了"的单次观察都不构成证据。

### 第 4 层：无效

- "解锁隐藏能力""突破参数限制""提升 IQ""让模型进入更高推理档位"。
- 通过提示词让模型获得它没有的知识（训练里没有的事实，只能靠检索或工具）。
- 通过提示词稳定获得超出该模型能力上限的结果。

## 三、agent 能不能自主优化自己的提示词

### 形式条件

任何优化都需要三件东西：搜索空间 **P**（候选提示词）、目标 **J**（好坏判据）、评估器 **E**（打分手段）。

- **P**：agent 能自己生成。改写、变异、组合，都不缺。
- **J / E**：**问题全在这里。**

如果 E 是"同一个模型 judging 自己的输出"，会同时踩三个坑：

1. **自偏好**：模型倾向于给自己（或与自己风格相近）的产出更高分。
2. **冗长偏好**：更长、更结构化、更"像样"的回答得分更高，与正确性弱相关。
3. **无 ground truth**：优化目标退化成"让输出看起来更讨自己欢心"，而不是"更对"。

文献里 OPRO、APE 这类"用 LLM 当优化器"的方法能work，前提都是**有一个外部的、可计算的评分函数**（开发集准确率之类）。没有它，优化循环就没有锚。

### 可行的形态：文本空间搜索 + 可验证代理

把 J 换成**可机械检查的代理指标**，优化就重新有了锚：

- 输出契约能否被解析（JSON 能不能 parse、表格列名对不对）
- 验收标准逐条是否被覆盖（每条能否指到具体证据）
- 未知项是否被标记（而不是被编造填满）
- 代码能否运行、测试能否通过、数字能否回代

这套代理优化的是**规格保真度**，不是**品味**。这是必须向用户说清的边界：它能把"你没说清所以做歪了"这类失败大幅压掉，但它判断不了"这个方案是不是最好的方案"——那需要领域判断和外部反馈。

### 三个必须承认的失效点

1. **代理鸿沟**。代理指标满分不等于用户满意。规格本身写错了，优化得越彻底，错得越整齐。
2. **意图替换**。把模糊需求改写成具体需求，等于替用户选了一种理解。选错了，产出流畅但答非所问——**这比直接问一句更糟**，因为它消耗了用户的信任却不给纠错机会。
3. **单次不可证**。提示词敏感性决定了：没有重复测量或确定性检查，"改进"只是叙事。

### 所以本技能的取舍

- 声称能做的：**规格完备度**的提升（可用诊断脚本前后对比，客观可查）。
- 不声称的：模型能力提升、方案优劣判断、"更懂你"。
- 用**三重审核**（事实层/意图层/可验证层）替代"自评打分"，用**假设台账**替代"静默决策"，用**确认闸门**兜住不可逆操作。

---

## 四、一句话总结

提示词不能改参数，但能改"模型被迫猜多少"。前者是能力问题，后者是规格问题。**绝大多数被归因为"模型不行"的失败，其实是规格不行**——这也是为什么这套东西值得做成流程，而不是靠临场发挥。
