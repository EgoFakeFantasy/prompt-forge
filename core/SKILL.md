# Prompt Forge

## 0. 这个技能优化的是什么（先读，防止过度承诺）

行为 = f(权重 θ, 上下文 c, 推理预算 τ, 可用工具)。提示词只作用于 c 与部分 τ，**不作用于 θ**。

所以本技能的目标不是"让模型变强"，而是：

> 把一段欠定义的请求，补全成一份**执行者无需猜测**的任务规格，然后按这份规格执行。

三条硬边界，任何时候不得跨过：

1. **不改权重。** "用特殊提示词提升参数能力"是范畴错误。提示词能做的是：补上模型无法推断的信息、压缩输出的方差、把串行计算（分解/自查）显式化。上限由 θ 决定。
2. **无外部验证时，自评"改得更好"不可信。** 同一模型评判自己写的提示词与其产出，存在自偏好与冗长偏好，且没有 ground truth。因此本技能用**可机械检查的代理指标**（规格槽位覆盖、验收标准可检查性、输出契约可解析性）替代"质量打分"，并明确标注这是代理指标。
3. **改写必然是一种解释选择。** 把模糊需求改写成具体需求，等于替用户选了一种理解。选错了，用户会得到一个流畅但答非所问的结果——比直接问更糟。因此每次改写都必须留痕（假设台账），高风险任务必须先确认。

详细的能力边界与证据分层见 `references/evidence-and-limits.md`。

## 1. 触发与不触发

**触发**
- 用户明确说：优化提示词、改写 prompt、帮我改一下这个需求、提示词自优化。
- 请求里有大量模糊词（"优化一下""好一点""适当""相关""等"），且交付物成本高（写代码、出报告、动数据）。
- 一次做错代价高的任务：涉及删除/覆盖、对外发布、付款、批量操作。
- 多约束任务（同时要满足格式、长度、技术栈、口径），漏一条就返工。

**不触发**
- 一句话事实查询、名词解释、闲聊。
- 规格已经精确（有路径、有格式、有验收标准）——此时改写只会引入噪声，直接执行。
- 用户只要一个快速草稿，明确表示"随便给个方向就行"。

判定依据不是感觉，是 P1 的脚本输出。

## 2. 流程

| 阶段 | 动作 | 产出 | 中止条件 |
|---|---|---|---|
| P0 | 抓取原始请求原文，不做任何转述 | 原文 | 原文缺失关键上下文（如"那个文件"）→ 进 P2 但强制询问 |
| P1 | 跑诊断脚本 | 规格分、缺失槽位、歧义、风险 | 脚本不可用 → 手工按第 3 节八个槽位逐项过 |
| P2 | 定档 T0–T3 + 风险定级 | 档位与理由 | T3 → 必须先确认 |
| P3 | 按六个不变量改写 | 改写稿 | 超长度预算 → 退回 |
| P4 | 三重审核 | 过审记录 | 任一层不过 → 回 P3 |
| P5 | 确认闸门（T2 有未决分歧 / T3） | 待确认问题 | — |
| P6 | 按改写稿执行 | 实际交付物 | — |
| P7 | 交付报告 + 记台账 | 改动表、假设台账、结果 | — |

用户只要求改提示词、不要求执行时，流程止于 P5。

## 3. 诊断：八个规格槽位

缺一项，执行者就得多猜一次；猜错就是一次返工。权重来自"猜错的代价"。

| 槽位 | 权重 | 缺失时执行者会怎么猜 |
|---|---|---|
| 目标动作 | 12 | 不知道要产出什么，可能只做分析不动手 |
| 交付物载体 | 15 | 文件？聊天里说？路径在哪？格式是什么？ |
| 受众与用途 | 6 | 术语密度、详略、要不要铺垫背景 |
| 硬约束 | 12 | 长度、风格、技术栈、版本、禁项 |
| 验收标准 | 18 | 不知道做到什么程度算完，只能自我感觉 |
| 输入材料指向 | 12 | "那个文件"是哪个，可能编一个 |
| 范围与边界 | 10 | 顺手把不该做的也做了 |
| 输出格式契约 | 15 | 结构随意，无法机械校验 |

用脚本跑，不要凭印象：

```bash
python scripts/prompt_audit.py audit --file <提示词文件>
# 或 cat req.txt | python scripts/prompt_audit.py audit
```

脚本输出规格分、缺失项及其对应改写动作、歧义信号、风险信号、建议档位。它是确定性规则匹配，跑两次结果必然一致，因此可以作为改写前后的对照基线。

## 4. 分档

脚本现在直接给**裁决**（`verdict`）：`skip` / `rewrite` / `confirm`，并给出理由。脚本只做清点，**不做最终裁决**——最终裁决走 4.5 的三问。

| 档 | 判据 | 动作 |
|---|---|---|
| T0 | 三问全否，或脚本判定 `skip`（形态契约已唯一确定 / 有终止出口 / 适用槽位齐全） | **不改写**，直接执行 |
| T1 | 缺 1–3 项，且三问有一项为"会猜错" | 微改写：只补输出契约 + 验收标准，不动原文措辞 |
| T2 | 歧义 ≥ 3 处或缺项 ≥ 4 项 | 完整改写 + 假设台账；若某假设会导致不可逆结果，进 P5 |
| T3 | 命中风险信号且规格分 < 55 | **先确认，后动手**。禁止静默执行 |

风险信号包括：不可逆写入、对外发布、资金交易、凭证权限。命中任一项，即使规格完整，也要在执行前复述一遍"我将要做什么"，让用户有一次叫停的机会。

## 4.5 覆盖条款：三问定生死（v3 新增）

**脚本分数低不等于需要改写。** 词表匹配天生会误判：一个"从 stdin 读、往 stdout 写、输出只允许结果本身"的脚本任务，没有受众、没有外部材料，脚本却会按缺槽位扣分，把一份精确的规格判成 T2。实测过：一段 92 字、已经精确到"标准输出只允许出现结果本身"的提示词，被旧版脚本判为 49 分 T2——照着改，就是把一份好规格改坏。

所以定档前必须过三问，**任一问为"会"才允许改写**：

1. **执行者会不会猜错目标？** 目标动作、交付物形态是否唯一？唯一 → 否。
2. **有没有用户没说、但猜错就要返工的硬约束？** 长度、技术栈、禁项、口径，用户没提且属领域默认 → 否。
3. **交付物能不能验收？** 用户已给出可判定的完成条件（含"只改这一行、其它不许动"这类）→ 否。

三问全否 → **T0，无论脚本多少分**。此时在交付里写一句"规格已足够，未改写"，并说明脚本报的缺项为什么不适用。

**这条优先级高于脚本**。技能是流程，不是算命；脚本负责不漏项，判断负责不误伤。

## 5. 改写的十三个不变量

- **I1 保意图。** 只能补"怎么做"，不得改"做什么"。把"优化一下代码"改写成"按我偏好的架构重写"属于劫持，不是优化。
- **I2 只加可验证项。** 每条新增内容要么是可检查的判据，要么是原请求缺失的事实。禁止"你是世界级专家""请深呼吸""这对我很重要"这类无信息量前缀——见 `references/evidence-and-limits.md` 第 3 层。
- **I3 显式假设。** 凡是我替用户做的决定，逐条写进假设台账，并标依据等级：**用户明说 / 领域默认 / 我的猜测**。第三级必须在交付时提示。
- **I4 约束只增不减。** 用户写的限制一条都不能删，哪怕看起来矛盾——矛盾要在报告里指出，不能悄悄消解。
- **I5 长度预算。** 改写后不超过原文 3 倍，**但绝对上限至少给到 600 字**——两者取宽。超过说明已经在写另一个任务。
  为什么需要这条下限（v6）：36 字的请求缺七个槽位，3 倍只有 108 字，压到 108 字必然重新变成欠定义。此时按 600 字上限，并在交付里说明为什么突破了比例。**比例是防注水的，不是让短请求永远无解的。**
- **I6 输出契约优先。** 预算紧张时，砍背景描述，保交付物骨架（小节标题、表格列名、字段名、文件路径）。
- **I7 素材对齐。** 改写新增的每一个输出字段，都必须在输入材料里有对应来源。材料里没有的，要么删掉这个字段，要么显式允许 `null / 未提供`——**绝不能留空让执行者自己填**，那是主动下指令制造幻觉。（v2 新增，见第 10 节实验证据）
- **I8 能力外置，别用提示词修能力。** 先判断瓶颈类型：**规格瓶颈**（执行者知道怎么做，但不知道要什么）→ 改写有效；**能力瓶颈**（算术、长链逻辑、精确复现）→ 改写无效。实测：对 4B 执行者加"先逐行列中间量再汇总"，成绩从 0.70 掉到 0.48；改成"写代码算"也只到 0.00。此时正确做法不是继续堆提示词，而是换路径——由 agent 用工具/代码把结果算出来，作为**事实材料**写进提示词，或者换更强的执行者。
- **I9 形态契约不可扩写。** 原提示词含"只输出 X / 整个回复只能有 X / 只准一行"这类**回复形态的绝对约束**时，一个字都不许加，包括验收标准和自检指令。理由：这类契约的语义是"回复的全部内容就是 X"，任何追加都在违反它；而弱执行者遇到"只准输出一行"+"请逐条自检 5 项"这种自相矛盾的要求，会把自检过程直接吐到回复里。实测：给一条裸表达式任务追加输出契约和 5 条验收后，回复从 1 行变成 31 行，得分 0.81 → 0.62。验收标准只能写进**给人看的交付报告**，不能进提示词。
- **I10 终止条件不可稀释。** 用户给出"若无法满足则只回 Y"这类异常出口时，必须原样保留、位置不变，且**不得在它之后追加任何验收条款**——追加等于把它降级成"交付分支之一"。实测：给一个"约束互斥则回 CONFLICT"的任务补了交付与验收说明后，执行者改为硬写代码，得分 1.00 → 0.88。

- **I11 置信度不衰减。** 假设台账里标为"我的猜测"的条目，**必须在最终结论句里保留同样的限定词**。正文写"可能是 X"，结尾不能写成"就是 X"。这类衰减在长报告里几乎必然发生：证据段越严谨，收尾越容易收紧。交付前做一次专项回扫——把结论句逐句对回台账，凡是等级被抬高的，改回去或补一句"（推断）"。同时必须列出**证据缺口**：哪些关键判断缺少直接证据、缺的是什么证据、如果拿到它结论会不会变。
- **I12 审美约束用锚定，不用指标。** 遇到"画风精美""有吸引力""高级感"这类审美要求，**不要**翻译成"对比度 ≥4.5、留白 ≥40%、字号层级 ≥3"——那会把设计做死，产出符合指标但没有味道的东西。审美意图只能通过三样东西传递：**参考锚**（指名风格、年代、具体作品或流派）、**反例**（明确不要什么：不要渐变紫、不要圆角卡片堆叠、不要 AI 味插画）、**场景**（谁在什么设备上看、看多久、看完要做什么）。可判定的部分只保留硬约束（响应式、可访问性、加载体积），其余交给锚定。
  **锚定要锚到"内容类型的视觉隐喻"，不是形容词。** 顺序是：先定内容类型（规则手册 / 产品发布 / 研究笔记 / 教程 / 图鉴）→ 再定该类型的视觉隐喻（手册 = 印刷品、衬线、编号、细线；产品 = 玻璃、渐变、大留白；研究 = 论文版式、脚注）→ 最后才用形容词做微调。反过来做（先挑形容词）会得到"好看但不对"的东西。
  另：**"第一眼强度"和"信息可检索性"是互相 trade-off 的两个目标**，必须选一个当主目标，不要同时最大化。

- **I13 指标要交代盲区。** 当多个指标都能描述同一现象时，必须说明所选指标会**低估或高估**什么，并至少给一个互补指标。反例（实测）：用"字节相同率 0%"描述两个代码分支，字面为真，但会让人以为没有重复——内容重复其实 91%。换成"同名文件的内容行重复率"才看得见。同理，用"文件数"描述测试覆盖会掩盖"用例数"，用"平均分"描述分布会掩盖长尾。**选指标不是中性的，它决定了读者看见什么。**

## 6. 三重审核（P4，必做，不可合并）

**审核一 · 事实层**：逐条问"这条新增内容的依据是什么"。无依据 → 降级为假设或删除。宁可规格薄一点，不要塞进编造的约束。**同时做素材对齐检查：每个被要求输出的字段，材料里有没有对应来源？没有就按 I7 处理。**

**审核二 · 意图层**：设想把改写稿原样交给一个完全不了解上下文的执行者。他的产出会不会偏离用户真实目的？会 → 改改写稿，而不是靠执行时临场纠偏。

**审核三 · 可验证层**：每条验收标准，能否在交付时被机械检查（数一遍、跑一遍、比对一遍）？不能 → 删掉，或改写成可检查的形式（"质量要好" → "每个结论附来源链接"）。

三层任一不过 → 回 P3。不允许带着未过审的稿子进入执行。

## 6.5 约束要可判定，不是要少（v2 修正）

初版写的是"弱执行者要少给约束"，实测把这个假设推翻了：**8 个字段 + 5 条可判定规则**的改写稿，在 4B 执行者上 3/3 次全过；**3 个字段但含"用一句话概括"**的极简版，3/3 次都漏掉关键信息。

结论：约束条数不是瓶颈，**每条约束能不能被判定**才是。

- 每条约束必须能回答"怎么判定它被满足了"。能判定的约束（字段名固定、缺值填 null、枚举限定、字数上限）越多越稳。
- 不可判定的要求（专业、简洁、合理、有深度）要么换成可判定的替代物，要么删掉——留着只会占预算并诱发自由发挥。
- 长度仍受 I5 约束（≤ 原文 3 倍），这是唯一该克制的维度。
- 唯一的"少"：不要在同一个提示词里既要求推理又要求格式，两者冲突时执行者会丢一个。先给结果，格式用输出契约兜住。

## 6.6 做多个美术方向时，先隔离变量（v4 新增）

要给同一个内容出多个视觉方案做对比时，**结构必须相同，只换视觉语言**。否则无法判断差异来自哪。

实测教训：一次对比里，深色方案同时改了配色**和**版式（人物从侧栏挪到标题背后居中），结果标题压在人脸上、可读性崩了。当时第一反应是"深色不好看"——其实是**结构错了**，跟颜色无关。把结构改回两栏之后，深色方案才变得可比。

流程：① 固定骨架（栅格、区块顺序、字号层级）→ ② 只换色彩/材质/图形语言 → ③ 截图并排看 → ④ 才能判断"哪个方向更适合这份内容"。跳过①，结论一定是错的。

## 7. 交付时必须给出

1. **改写稿**——完整、可直接复制，不省略。
2. **改动表**——加了什么 / 为什么加 / 依据等级。三列，不写长篇解释。
3. **假设台账**——"我的猜测"级的条目单独标出。
4. **证据缺口**——哪些关键判断没有直接证据、缺什么、拿到之后结论会不会变。（I11）
5. **残余风险**——仍未解决的歧义、代理指标覆盖不到的地方。
6. **执行结果**——按改写稿真实执行后的产出。

只做 T0 时，省略 1–3，直接给结果，一句话说明"规格已足够，未改写"。

**优先级（v3 明确）**：用户的输出契约（I6/I9）> 本节的交付格式。当用户要求"整个回复只能有 X"时，**不要**把改写稿、改动表、台账塞进回复——那会直接违约。此时把交付报告放进执行结果之后的附注、或单独的说明文件，或者干脆省略，只在末尾用一行说明"已按原样执行，未改写"。

## 8. 反模式

- 把模糊需求改写成"我习惯的做法"，然后当作需求执行。
- 加人设、加鼓励、加恐吓来"提升表现"。
- 用改写掩盖信息缺失：不知道数据在哪，就编一个像样的路径。
- 拿自己的评分当改进证据。
- T3 任务静默执行，事后才说"我删了这些文件"。
- 为了显得做了工作，把一段清楚的请求改得更长。

三臂对照：raw（用户原话）/ placebo（原话 + "请仔细思考，确保准确完整"）/ forged（本技能的改写稿）。
判分：全部确定性脚本检查，无模型评判。

| 任务 | 档 | raw | placebo | forged |
|---|---|---|---|---|
| 数据汇总（JSON 契约） | T1 | 0.00 | 0.00 | 0.70 |
| 日志统计脚本 | T1 | 0.47 | 0.40 | 0.87 |
| 清理临时文件（不可逆） | T3 | 0.67 | 0.92 | 1.00 |
| 客户故障说明（多硬约束） | T2 | 0.61 | 0.56 | 0.83 |
| **平均** | | **0.44** | **0.47** | **0.85** |

代价：提示词 136 → 381 字（+180%），输出 1363 → 561 字（−59%）。

三条被实验修正的结论：

1. **I7 素材对齐是真问题。** v1 的客户说明要求写"发生时间/补偿"，但材料里没有这些事实，4B 直接编了"今日下午"。补上事实材料并要求"材料未提供则填 null"后，该任务 0.83 → 0.94。
2. **"先列中间量再算"是错的处方。** 同一数据任务从 0.70 掉到 0.48；改成"写代码算"也只到 0.00。4B 执行者的瓶颈是算术能力，不是计算纪律。→ 催生 I8。
3. **"弱执行者要少给约束"是错的。** 兼并测试里，另一个 agent 只读本文件写出的 8 字段改写稿 3/3 次全过（1.00），而 3 字段极简版 3/3 次漏关键信息（0.80）。→ 修正为 6.5。

**适用边界**：以上收益来自"补规格"，不是"提能力"。任务瓶颈在能力侧时，本技能收益趋近于零，应改走工具/代码路径。

### 10.1 红队攻击与 v3 修正

让一个子 agent 专门设计"能让本技能失效"的编程任务，产出四个攻击面，全部配确定性判分：

| 攻击 | 打的是哪个机制 | 结果 |
|---|---|---|
| 精确到"stdout 只允许结果本身"的脚本任务 | 诊断脚本按词表扣分，把精确规格判成 49 分 T2 | **命中**：旧版会强行改写 |
| "只改这一行，不许加注解/docstring/注释" | I4 只拦删除，不拦"把禁项当待办去做" | 未击穿（改写反而 +0.14） |
| "整个回复只能有一行裸表达式" | §7 强制交付报告，与 I6 冲突 | 部分命中：回复被撑到 31 行 |
| "递归 + n=2000 + 不许调栈深，无解则回 CONFLICT" | 没有约束可满足性检查 | **命中**：改写稀释了终止出口，1.00 → 0.88 |

三臂对照（raw 原话 vs v2 技能改写稿，4 次重复）：**0.84 vs 0.85**。差异在噪声内——也就是说，**在本来就精确的提示词上，v2 的改写不产生净收益，只是白花 token，并且局部有损伤**。

根因三条，全部写进了不变量：

1. 脚本是词表匹配，缺槽位不等于有猜测面 → **4.5 三问覆盖条款**（脚本只清点，判断负责不误伤）。
2. 对"只输出 X"的形态契约追加验收，等于自相矛盾 → **I9**。
3. 在"无解则回 Y"之后追加验收，等于把出口降级 → **I10**。

v3 复测（同一批攻击，同样的字面执行者）：**四个全部判 RAW，零改写**，得分等同基线且不花额外 token。反向验证同时通过：真实欠定义的汇总任务仍被判 T2 并改写，且执行者自发套用 I8（先把 Decimal 汇总结果算好写进提示词），数值正确率 **3/3**（v1 改写稿为 0.70）。

### 10.2 v4：两条来自"非提示词任务"的规则

**I11 的来源是一次调研评测。** 让子 agent 去考证一个 GitHub 仓库的作者模型，它在正文里严谨地把结论标成"合理推断（强）"，在结尾总结里却写成了陈述句"这是一个用 X 写的产物"。证据段越扎实，收尾越容易收紧——这是长报告的通病，与领域无关。所以 I11 要求在交付前把结论句逐句对回台账。

**I12 的来源是一次审美任务。** 要求"画风精美"时，把"精美"翻译成可判定指标（对比度、留白率）会让产出符合指标但没有味道；正确做法是给参考锚、反例、场景。同一份内容做两个美术方向对比时还发现：**深色方案同时改了配色和版式，结果标题压在人脸上、可读性崩了**——第一反应是"深色不好看"，实际是结构错了。所以对比多个方案必须先固定骨架、只换视觉语言，否则结论一定是错的（见 6.6）。
