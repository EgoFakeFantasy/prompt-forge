# prompt-forge 红队测试报告：让技能失效

日期：2026-10-21　被测技能：prompt-forge v2 → v3　被测模型：`qwen3.5:4b`　判分：全确定性

---

## 1. 什么叫"让技能失效"

不是"题目太难让模型答不出"。是这个意思：

> **改写之后，结果比不改更差，或者一点没变好——但多花了成本、多承担了风险。**

所以攻击样本必须是**本来就写得不错的编程提示词**。这类输入对改写技能的收益空间最小、翻车空间最大。四个攻击样本的正确做法往往就是"别动"，这正是最容易被技能破坏的地方。

---

## 2. 红队产出：四个攻击面

由子 agent 独立设计（只给了它技能路径和"必须可机械判分"的约束），每个都指向机制而非难度：

| # | 攻击 | 打的是哪个机制 |
|---|---|---|
| A1 | 精确到"标准输出只允许出现结果本身"的脚本任务 | 诊断脚本按词表扣分，把精确规格判成 **49 分 T2**，强制改写 |
| A2 | "只改这一行 return，不许加注解/docstring/注释/测试" | I4 只拦删除，拦不住"把禁项当待办清单去做" |
| A3 | "整个回复只能有一行裸表达式，不要围栏不要解释" | §7 强制交付改写稿+台账，与 I6「输出契约优先」直接冲突 |
| A4 | "递归 + n=2000 + 不许调栈深；无法同时满足则只回一行 CONFLICT" | 全流程没有约束可满足性检查；终止出口会被新增验收稀释 |

判分全部是脚本：跑代码、比对行数、`eval` 表达式、检查 stdout 字节。判分器先做了 12 例好/坏答案自检（含"友好报错版""加了类型注解版""被说明文字包住的表达式""偷偷 setrecursionlimit 版"），全部符合预期才用于实验。

---

## 3. 第一轮：判断型执行者（技能活下来了，但不是我该高兴的方式）

让一个子 agent 只读 SKILL.md 处理这四个请求。结果：**四个全判 T0，全部 NO_REWRITE**，而且答案本身都对。

看起来是技能赢了。但看它的理由：

> "脚本报的'受众/输入材料'对自包含脚本无意义，属模板误报"

**它推翻了脚本。** 而脚本给的 T2、以及第 4 节写的"规格分 ≥78 才是 T0"，都在明确要求它改写。它靠自己的判断救了这个技能——技能本身是错的，只是执行者够聪明。

这个结论很重要：**技能的可信度不能建立在"使用者会自己纠错"上**。换个弱一点的、或者更听话的执行者，就会照着脚本改，把好规格改坏。

---

## 4. 第二轮：字面执行者（攻击命中）

于是换一种测法：明确要求"按文档字面执行，档位以脚本输出和阈值为准，不要用你的判断覆盖判据"。这是对技能**成文规则**的忠实测试。

| 任务 | raw（原话） | v2 技能改写稿 |
|---|---|---|
| A1 词表盲区 | 0.80 | 0.80 |
| A2 负向约束 | 0.86 | **1.00** |
| A3 极简契约 | 0.69 | 0.72 |
| A4 约束互斥 | **1.00** | **0.88** |
| **平均** | **0.84** | **0.85** |

4 次重复。结论：

- **净收益约等于零**（+0.01，噪声内）。在已经精确的提示词上，改写没有价值。
- **A4 稳定受损**：4 次里 1 次从"回 CONFLICT"变成硬写代码，然后 RecursionError。根因清楚——改写把 ④ 从"唯一出口"降级成"交付的两个分支之一"，又追加了"count_paths(2000) 必须返回整数"的验收，等于在鼓励它去硬跑。
- **A2 反而变好**（+0.14）：补上"块外无任何文字"确实减少了多余解释。说明改写不是一无是处，只是收益不来自"更详细"，而来自"补上真正缺的那一条"。
- **A3 的差异是噪声**：2 次重复时看着像从 0.81 掉到 0.62，加到 4 次就基本抹平了。**这条本身就是教训——单次观测不足以判断提示词好坏，这正是技能该坚持"确定性判分"的原因。**

---

## 5. 根因：三条，全在技能自己身上

1. **脚本是词表匹配，缺槽位 ≠ 有猜测面。** 一个"读 stdin、写 stdout"的脚本没有受众、没有外部材料，脚本照样按缺槽位扣分。92 字的精确规格被判 49 分 T2。
2. **对"只输出 X"追加验收，逻辑上自相矛盾。** 这类契约的语义是"回复的全部内容就是 X"，追加的任何字都在违反它；弱执行者面对"只准一行"+"请自检 5 项"的冲突，会把自检过程直接吐出来（实测 1 行 → 31 行）。
3. **在终止出口之后追加验收，等于把它降级。** "无解则回 Y"必须保持唯一性，任何后续条款都会被当成"要优先满足"。

---

## 6. v3 修正

**脚本层**

- 增加**槽位适用性**：code / transform 类任务不再因为"受众""输入材料"扣分。
- 输出从"档位"改成**裁决**（`skip` / `rewrite` / `confirm`）+ 理由，脚本只清点不裁决。
- 新增 `form_contract`（只输出/只能有/原样输出…）与 `has_termination_clause`（无解则回…）两个检测器，命中即建议跳过。
- 识别"只输出/只允许/原样输出"本身就算输出格式契约——旧版不认，是 A1 误判的直接原因。

**规则层**

- **§4.5 覆盖条款**：三问（会不会猜错目标 / 有没有没说但猜错就返工的硬约束 / 能不能验收），三问全否 → T0，**无论脚本多少分**。这条优先级高于脚本。
- **I9 形态契约不可扩写**：命中"只输出 X"类约束时，一个字都不加，验收标准只进交付报告，不进提示词。
- **I10 终止条件不可稀释**：异常出口原样保留、位置不变，其后不得追加验收。
- **§7 降级为默认格式**：与 I6/I9 冲突时，以用户的输出契约为准。

---

## 7. 复测

**攻击集（v3 + 同样的字面执行者）**：四个全部判 `RAW`，零改写。得分等同基线，不花额外 token，不再有 A4 那种"改写反而写坏"的风险。

**回归（防止修成废物）**：四个原本欠定义的请求仍全部判 `rewrite / T2`。并且拿真实汇总任务做了一次端到端验证——v3 的执行者不但改写了，还**自发套用了 I8**：先把 Decimal 汇总结果算好、作为事实材料写进提示词，明确要求"不要重新计算"。结果 **3/3 次数值全对**（v1 的改写稿是 0.70，小模型自己算必错）。

也就是说，v3 不是"改少了"，是**改在该改的地方**。

---

## 8. 还没修掉的（诚实清单）

- **脚本仍是词表匹配**。"把结果原样吐出来"这类说法不一定触发 `form_contract`；换个说法就能绕过去。它永远只是清点工具。
- **§4.5 依赖判断力**。如果使用者本身是弱模型，"三问"很可能被草率地回答"否"，从而漏改写。这个方向没测。
- **§7 与 I6 的冲突只是用文字排了优先级**，没有机制性保证；执行者仍可能把报告塞进回复。
- **样本量小**。4 个攻击任务、4 次重复，能看出方向，不足以支撑精确结论。A3 就是活例子。
- **只测了"该不该改"，没测"改得对不对"**。改写方向错了（比如把 T2 写成过度约束的稿子）这一类失败没有覆盖。
- **单一被测模型**。4B 的表现不能外推到强模型；强模型上这些差异大概率会缩小。

---

## 9. 一句话结论

红队这次没有把技能打死，但把它的**虚假自信**打掉了：v2 在精确输入上"看起来能改写"，实际净收益为零还带风险；根因是它把**词表清点**当成了**规格判断**。

v3 的改动没有让技能更强，而是让它**更知道自己什么时候该闭嘴**——这恰好是这类技能最该具备、也最容易缺的能力。
