# prompt-forge 技能实测报告

日期：2026-10-21　被测对象：`qwen3.5:4b`（本地 Ollama）　判分：确定性脚本，无模型评判

---

## 0. 关于测试对象的说明（先纠正一处前提）

要求里指定"本机 qoder 中的 qwen3.8flash"。实测本机情况：

- **Qoder 是纯 Electron IDE**，安装目录下只有 `Qoder.exe` 与 Electron 运行时，**没有 CLI 入口**，无法被脚本调用；其内部模型凭据加密存储，也不应被抓取复用。
- **不存在名为 `qwen3.8flash` 的模型**。本机 Ollama 里实际可用的 qwen 模型是 `qwen3.5:4b`（Qwen3.5-4B-Base，Q4_K_M，2.46 GiB，4.21B 参数）。

因此测试对象改为 **`qwen3.5:4b`**。这个替换反而更合适：4B 小模型是指令跟随最脆弱、也最能暴露规格缺失的一档；在强模型上做这种测试，天花板效应会把差异抹平。

服务用 `OLLAMA_KV_CACHE_TYPE=q8_0 OLLAMA_NUM_PARALLEL=1` 启动（本机可用内存仅 ~4 GB）。**关键设置：`think=false`**。首次运行未关思考通道，600 token 全部耗在 thinking 里、`content` 为空，36 次调用全部记 0 分——这批数据已作废，重跑。

---

## 1. 方法

**三臂对照**，同一模型、同一温度（0.7）、同一判分：

| 臂 | 内容 | 作用 |
|---|---|---|
| raw | 用户原话（含必要路径/数据，但缺规格） | 基线 |
| placebo | 原话 + "请仔细思考，确保准确完整专业，满足所有要求" | **关键对照**：只加鼓励、不加信息 |
| forged | 按 prompt-forge 改写后的稿 | 处理组 |

placebo 臂是整个实验的支点。没有它，"改写稿更好"只能说明"多写点字更好"。

**4 个任务**覆盖四个档位，全部配确定性判分：

| 任务 | 档 | 判分项 |
|---|---|---|
| 销售数据按区域汇总 | T1 | 9 项：JSON 可解析、字段集精确、订单数、金额误差 ≤0.02、降序、无多余解释 |
| 日志统计脚本 | T1 | 5 项：抽出代码、函数签名、**实际执行**、返回值 ERROR=3/WARN=2、无第三方依赖 |
| 清理临时文件 | T3 | 4 项：未声称已删除、先扫描列清单、要求确认、未给出可直接执行的破坏性命令 |
| 客户故障说明 | T2 | 6 项：≤120 汉字、无内部技术名词、含时间/影响/补偿、未承诺恢复时间 |

判分器本身先做了自检（11 例好/坏答案，含"字段多一个""数字错一位""文案含 Redis"等），全部符合预期才用于实验。

---

## 2. 主结果

每臂 3 次重复，表中为检查项得分率均值。

| 任务 | 档 | raw | placebo | forged |
|---|---|---|---|---|
| 数据汇总 | T1 | 0.00 | 0.00 | **0.70** |
| 日志脚本 | T1 | 0.47 | 0.40 | **0.87** |
| 清理文件 | T3 | 0.67 | 0.92 | **1.00** |
| 客户说明 | T2 | 0.61 | 0.56 | 0.83 |
| **平均** | | **0.44** | **0.47** | **0.85** |

- 相对 raw：**+0.41**；相对 placebo：**+0.38**。
- 4 个任务方向全部一致，3 次重复无翻转。
- 代价：提示词 136 → 381 字（+180%），**输出 1363 → 561 字（−59%）**。总字符数反而从 1499 降到 942。

placebo 只比 raw 高 0.03，且在两个任务上低于 raw——**"让模型更努力"基本无效，"把要求说清楚"才有效**。这条是整份报告里最稳的结论。

## 3. 迭代：三轮打回与两处架构修正

第一轮结果里，forged 并非全胜。逐项看残余失败，暴露了两处**我自己的改写稿**的缺陷。

### 3.1 修正一：素材对齐（I7）

客户说明任务 0.83，失败项恒为"含补偿/后续动作"。看输出：

> "今日下午发生短暂服务波动，部分用户下单受阻。我们已启动优化方案并同步排查原因……"

两个问题：① 材料里根本没有"发生时间"，模型自己编了"今日下午"；② 没写补偿。

根因不是模型不听话，是**我的改写稿命令它输出一个材料里不存在的事实**。这不是缺约束，是缺素材——而且是指令级地诱发幻觉。

修正：新增 I7「改写新增的每个输出字段，材料里必须有来源；没有就显式允许 null，不能留空让执行者填」；同时把事实材料（时间/影响/补偿）直接写进提示词。

复测：**0.83 → 0.94**（3 次里 2 次满分）。

### 3.2 修正二：能力外置（I8），并推翻一个错误处方

数据汇总任务 0.70，格式全对、数字全错（订单数 4/4/4 被算成 3/3/6、4/3/5）。第一反应是加"计算纪律"：

> ① 先逐行写下每行的 region 与 amount，共 12 行；② 再按 region 数行数、累加；③ 自检求和。

复测：**0.70 → 0.48，更差了**。三次输出数字依然全错，还多了一次 JSON 语法错误。

再换思路，要求它**写代码算**（"不要心算，写脚本，数据内嵌，print JSON"）：**0.00**。4B 写出的脚本引用了未定义的 `reader`，还在代码注释里自言自语，从未产出 JSON。

结论反过来了：**这个任务的瓶颈是算术能力，不是计算纪律**。任何形式的"让执行者算得更仔细"都无效，包括让它写代码——写对代码也是能力。

于是 I8 从"计算纪律"改写成"**能力外置**"：先判断瓶颈是规格还是能力；能力瓶颈时改写收益趋近于零，应改走工具路径（agent 自己算完把结果当材料）或换执行者。这条同时是"什么时候不该用这个技能"的判据。

### 3.3 修正三：推翻"弱执行者要少给约束"

兼并测试（见下）里，8 字段改写稿 3/3 全过，3 字段极简版 3/3 漏关键信息。原稿 6.5 节写的"硬约束 ≤5 条、字段 ≤5 个"被自己的数据推翻，改成「**约束要可判定，不是要少**」——能判定的约束越多越稳，不可判定的（专业、简洁、有深度）才是噪声。

## 4. 兼并测试：另一个 agent 只读 SKILL.md 能否复现

给一个全新子 agent 的任务只有三件事：技能路径、用户原话、输出格式要求。**不告诉它怎么做**。它自己读了 SKILL.md，判定 T2、跑了诊断脚本、写出改写稿、列了 7 条假设台账（其中 4 条标注"我的猜测"）。

任务是一个带陷阱的客服对话抽取：客户先问"能不能退钱"，紧接着说"不，先别退"。

| 臂 | 得分 | 提示词字数 |
|---|---|---|
| raw | 0.60（3/5） | 167 |
| 子 agent 改写（8 字段） | **1.00（5/5，3 次全过）** | 699 |
| 我写的极简版（3 字段） | 0.80（4/5） | 313 |

raw 输出的是 markdown 表格，不是 JSON，直接丢掉两项。子 agent 版每一项都对：`product: null`（原文没提商品型号，它按"素材未提供则填 null"处理）、`deadline: "9 月 18 号"`（照抄不换算）、`withdrawn_request: "退钱"`（把撤回的诉求单独留档）。

这条测试回答了一个关键质疑：**主实验里的 forged 稿是我这个"知情者"写的，算不算作弊？** 兼并测试里子 agent 并不知道标准答案，只凭原话 + 技能，就写出了同等甚至更好的稿子。说明"从原话推断该补什么"是可迁移的，不是靠我偷看答案。

## 5. 结论：值不值得单出 skill

**值得，但边界必须写死。**

支持它的三条：

1. **提升幅度大且稳定**：+0.38（对 placebo），4/4 任务同向，3 次重复无翻转。且 placebo 证明这不是"鼓励效应"。
2. **成本不升反降**：提示词变长 180%，但输出缩短 59%，总字符数下降。规格越清，废话越少。
3. **可迁移**：另一个 agent 只读 SKILL.md 就能复现效果（1.00 vs 0.60），说明它是一份**可执行的流程**，不是一段我个人的写作习惯。

不支持无边界推广的两条：

1. **能力瓶颈无效**。算术、长链逻辑、精确复现——改写一点忙都帮不上，硬加要求还会反伤（0.70 → 0.48 有实测）。
2. **有过度改写风险**。我自己第一轮的稿子就同时犯了"要求材料里没有的事实"和"给弱执行者加无效的计算纪律"两个错。所以假设台账和残余风险不是形式主义，是这套东西唯一的纠错口。

一句话：**它值钱的地方不是"让模型变强"，是"让模型不用猜"**。凡是失败原因能归到"你没说清"的场景，它有效；归到"它不会"的场景，它无效，别浪费时间。

---

## 6. 局限（这些数字能推到哪一步）

- **单一被测对象**。只有一个 4B 模型，没有跨模型验证。强模型上差异大概率会缩小，本报告不外推。
- **3 次重复**。够看出方向，不够做显著性检验；提示词敏感性决定了这个样本量不能下"精确提升 X%"的结论。
- **think=false**。关掉思考通道是为了让三臂可比（否则 token 全被思考吃掉），但真实使用中开着思考的模型可能对提示词改写不那么敏感。未做敏感性对照。
- **判分是代理指标**。它测"是否满足可判定的要求"，不测"方案是否最优"。0.85 不代表好 0.85，只代表"该做到的都做到了"。
- **任务是我设计的**。虽然兼并测试用了子 agent 独立改写，但任务本身仍由我挑选，存在选择偏差。
